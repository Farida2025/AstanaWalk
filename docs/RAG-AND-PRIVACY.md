# RAG, ограничения и геолокация

## Что именно является RAG

Сбор → нормализация → локальная база → эмбеддинги описаний → извлечение условий → фильтры → смысловой поиск → погода/маршруты/расписание → выбор по найденным ID и фактам → проверка сервером → карточки и карта.

Используется готовая Gemini, обучение собственной модели не производится. Документ места составляется из имени, рубрик, доступных атрибутов, среднего чека и сводки полей источника. Эмбеддинги документов хранятся в локальном JSON; для запроса рассчитывается отдельный вектор. Сходство — cosine similarity. Перед смысловым поиском применяются структурные ограничения; индекс не заменяет проверку бюджета и подтверждённых признаков.

Первый запрос к модели извлекает условия, но не придумывает заведения. Затем программа получает до восьми смысловых кандидатов; после контекстной сортировки до трёх получают пешие маршруты. Второй запрос к модели выбирает только IDs кандидатов, ключи подтверждённых объяснений и короткий/обычный вариант длительности. Сервер проверяет ID, число/повторы рекомендаций и принадлежность ключей фактов конкретному месту. Фактические строки подставляются из базы.

Это ограниченная структурированная генерация, а не свободный туристический рассказ. Плюс — меньше возможностей выдумать услугу; минус — менее гибкая формулировка. Семантическая релевантность и корректность извлечения намерения всё равно требуют оценки людьми.

## Три вида информации

**Данные источника:** «В справочнике указан Wi-Fi», средний чек с оговоркой, расписание и рубрика. Ссылка ведёт к источнику; признак может устареть.

**Неизвестное:** нет стоимости билета, точного возраста, свободного сеанса или подтверждения услуги. Неизвестное не превращается в «услуги нет». Обязательное неизвестное условие не считается выполненным.

**Оценка прототипа:** ориентировочная длительность визита по категории, предположение о помещении, пригодность по времени при расчётном маршруте. Это не длительность конкретного сеанса и не гарантия.

## Время, погода, маршрут

Время интерфейса — Астана, UTC+5. Начало и длительность — разные поля. «Через два часа» задаёт начало относительно текущего момента, «у меня 90 минут» — бюджет дороги в одну сторону и визита. Возвращение не учтено.

Для чата проверяются прибытие и минимальный визит; максимальная предложенная длительность ограничивается известным закрытием и оставшимся временем. Если минимальный визит не помещается, вариант исключается. Неизвестное расписание/маршрут маркируется; при строгом фильтре открытия такой вариант не проходит. Каталог по фильтрам проверяет открытие только на стартовое время и прямо сообщает это.

Прогноз относится к исходной точке и приблизительно характеризует небольшой район, не каждую улицу маршрута. Проверяется непрерывное почасовое покрытие перехода и визита, а не только первый/последний час. Пропуск измерений или выход за горизонт означает «не подтверждено». При неограниченном времени первичный запрос проверяет четыре часа; более длинное посещение может остаться без полного покрытия.

Порог плохой погоды — эвристика прототипа: осадки, температура ≤ −15 °C или ≥ 30 °C, порывы ≥ 15 м/с. Это не медицинская/метеорологическая рекомендация о безопасности. Предпочтение помещений выводится из категории и не подтверждает конкретное устройство заведения. Явный запрос прогулки не заменяется кафе без согласия.

## Сбои и ограничения

При недоступном/устаревшем индексе или ошибке query embedding остаются фильтры и ключевые слова с явной отметкой. При неверном втором ответе Gemini используется шаблон из подтверждённых данных, также с отметкой. Сбой первого запроса извлечения намерения показывает ошибку; ручной каталог остаётся доступен. Нельзя выдавать эти режимы за успешный полный семантический RAG.

Проверяется не более трёх маршрутов. Если все они не подходят по прибытию, поиск не перебирает автоматически весь остаток базы: пользователь получает предложение изменить условия. Радиус означает расстояние по прямой; маршрут может быть длиннее и может выходить за круг. Точка старта и записи базы ограничены фиксированной областью 2 км.

Нет подтверждений тишины, розеток, наличия столиков/сеансов, билетов, точных возрастных ограничений, автобусных расписаний, такси или полноценной доступности маршрута. Детское меню/детская рубрика не означают возрастную пригодность. Обязательные ограничения требуют источника, а не догадки. Факты Wikipedia подключены для Хан Шатыра, а не для всех достопримечательностей города.

## Что передаётся и хранится

| Получатель | Передаваемые сведения |
|---|---|
| Сервер приложения | Выбранные координаты, время, фильтры и текст запроса |
| Gemini | Текст, до четырёх предыдущих пользовательских сообщений, условия и извлечённые записи/факты; отдельные поля точных координат исходной точки не добавляются |
| Gemini Embedding | Описание документов при индексации; текст запроса и ограниченный предыдущий контекст при поиске |
| 2ГИС Routing | Начальная и конечная точки |
| Яндекс Погода | Исходная точка |
| Wikipedia | Название запрашиваемой статьи |
| Leaflet CDN / OpenStreetMap | При загрузке карты: сетевой адрес и запросы ресурсов/области карты |
| Внешняя ссылка 2ГИС | Выбранные точки маршрута при переходе по ссылке |

Текст пользователя, названия мест и расстояния могут косвенно раскрывать район. Это **не анонимизация**. Автоматический GPS не запрашивается; точку пользователь задаёт сам. Карта загружается после нажатия. API-ключи остаются на сервере.

История — только в памяти вкладки, без localStorage/cookies приложения. Очистка исключает историю из будущего контекста, но не удаляет уже полученные провайдерами данные. Сервер не записывает тексты/координаты в файлы; кеш ответов маршрутов/погоды — до пяти минут, максимум 100 записей в памяти. Солевые хеши socket IP используются в ограничителе частоты; истёкшие записи удаляются при следующем API-запросе, карта ограничена размером. Это не обещание отсутствия сетевых логов у хостинга/провайдера.

Для публичного демо нужны HTTPS, секреты хостинга, настройка Origin, проверка логов и условий обработки/хранения внешних сервисов. Прототип не проходил независимый аудит безопасности или юридическую проверку.
